Financial metrics and Gate B tests

Every metric we calculate and every test a strategy must pass: the formula, and how to read it.

Part 1 is what the Lightyear dashboard shows. Part 2 is SE Return Analytics, the monthly block, which is now on the dashboard and in the workbook. Part 3 is Gate B v3: four hard blocks and three scorecard rows, with the deflated Sharpe shown outside the gate.

There are no run results or examples here. The only numbers are method settings and pass marks, checked against the code.

Part 1. On the Lightyear dashboard

1.1 The five headline numbers

These tiles appear on every run's Results tab, for the strategy and the benchmark over the same days. The comparators table repeats CAGR, volatility, Sharpe and worst fall for each alternative.

CAGR: the steady yearly growth rate from start to finish

CAGR=(VendVstart)1years−1

Volatility: how much returns swing in a year. Lower is a smoother ride

Vol=stdev(rdaily)×252

Sharpe (risk-free rate 5%): return above the risk-free rate, per unit of risk. Higher is better

Sharpe=CAGR−5%Vol

The 5% is the risk-free rate, a yardstick. It is not income the strategy earns: idle cash earns the card's cash rate. This headline Sharpe is the geometric form. Figures for a single calendar year, and every Gate B test, use the arithmetic form shown in 1.3.

Worst fall from peak (maximum drawdown): the biggest loss from a high to a later low

Max drawdown=maxt(1−Vtmaxs≤tVs)

100 became: what 100 grew into, after every daily return

Final=100×∏t(1+rt)

Part 2. SE Return Analytics (monthly)

A separate block, on monthly returns. It is on the Results tab and in the workbook sheet "SE Return Analytics". Every figure uses calendar-month returns m compounded from the daily returns, the population standard deviation, and three inputs: risk-free rate 5%, Omega threshold 1% a month, drawdown limit 0%. Do not compare a figure here with a daily figure of the same name in Part 1. Gate B uses none of them. The benchmark is the price index.

Python and Excel calculate each metric separately. Python calculates it in ros/metrics/se.py; Excel calculates it from a live formula in the workbook. The workbook's "Python vs Excel" sheet sets the two side by side and marks each OK or FAIL at 1e-9.

Part 3. The Gate B v3 tests

3.1 What a strategy must pass

Each test rules out one way a backtest can fool you. The pass marks are fixed in config before the run, so nobody can move the bar after seeing the answer. Every test reads the run's daily returns at the cost on its approved card. Hard blocks decide the status. Scorecard rows are shown green, amber or red and do not block.

#TestMethodPass markCounts as
1Implementable within the fund's mandateRule check on actual positionsNo breachHard block
2Data integrityChecks, card rules, priced coverageAll pass; coverage ≥ 90%Hard block
3Edge over the benchmarkCAGR gap> 0Hard block
4Advantage over benchmark is significantPaired stationary bootstrapP ≤ 0.1Hard block
5Sub-period stabilitySharpe gap in 4 windows≥ 50% of windows ahead; none below -1.0Scorecard
6Alpha survives the factor regressionRegression t-test with HAC errorsα > 0 and t ≥ 2.0Scorecard
7Performance after publicationEdge after the paper's dateEdge > 0%Scorecard

Status is PASS or FAIL. It is PASS when no hard block failed and tests 3 and 4 both ran and passed. The scorecard informs the reader and never blocks. "Not run" means a test had nothing to run on, for example no mandate limits on file. It is not a pass, it is listed beside the status, and it does not hold the gate up.

Tests 3, 4 and 6 are the statistical tests. Test 5 is a stability test, test 7 asks whether the edge outlived publication, and tests 1 and 2 are practical checks. The deflated Sharpe (3.9) is outside the gate, so the gate does not test for selection luck.

Lightyear reads each row as PASS, FAIL, green, amber, red or not run. "Evidence supports" on the Gate B tab is written by Claude, not calculated, and the decision stays PENDING until a named person records it.

3.2 Test 1: implementable within mandate

The question. Could the fund actually hold these positions?

Method. A rule check on the positions actually held, not the settings: the largest cash share, the largest single weight and the lowest weight, against the fund's limits. A card cannot change the limits; an override needs a named person and a time, and is shown. Pass: no breach. If it fails: each breach is listed.

Watch out: the limits file must hold all three limits. If any is blank the row shows not run, which is not a pass.

3.3 Test 2: data integrity

The question. Can the numbers be trusted before any statistic is read?

Coverage=∑priced members × sessions∑all members × sessions

Method. Three things from the run's own files: every look-ahead and accounting check the run wrote passed; Lightyear's audit of the card's rules found none broken; and enough index members had a price. Pass: all checks pass, no rule broken, coverage ≥ 90%. If it fails: the result rests on a broken check, a rule the run did not follow, or too many members with no price.

Watch out: members never priced are a survivorship risk even above the mark. They are named in the evidence.

3.4 Test 3: edge over the benchmark

The question. Did it beat the index at all?

Edge=CAGRstrategy−CAGRbenchmark

Method. Both CAGRs over the same days, at the cost on the card. Pass: edge > 0. If it fails: the strategy did not beat the index it is measured against.

Watch out: on a card set to zero cost this is before any trading cost, so read the turnover and the cost sweep. The benchmark is a price index, which flatters the edge.

3.5 Test 4: paired stationary bootstrap

The question. We cannot re-run history. If we rebuild alternative histories from the real one, how often does the edge over the benchmark disappear? (Politis and Romano, 1994.)

The actual history, in order

One bootstrap draw: blocks of real days, in random order, with random lengths, to the same total length

The strategy and the benchmark are cut at the same days on each draw. That is what "paired" means.

  • Build: pick a random start day and take a block of days, with random lengths, until the history is full length. Blocks keep calm and stormy spells together. The average block length is chosen from the data (Politis and White, 2004), as the largest of the lengths for the strategy, the benchmark and their difference.
  • Pair: cut the strategy and the benchmark at the same days, which preserves their correlation.
  • Score: calculate each arithmetic Sharpe, mean(r − Rf) ÷ stdev(r − Rf) × √252 with Rf at 5%, on that history, and take the gap D.
  • Repeat 2,000 times with fixed seed 7, so the result can be reproduced.
D=Sharpestrategy−SharpebenchmarkP=number of draws with D≤0number of draws

Pass: P ≤ 0.1. If it fails: the gap over the index could be noise. Watch out: P is a share of re-shuffled histories, not the chance the strategy has no edge. Values just either side of the mark are nearly the same evidence. It looks at Sharpe only, so a shallower drawdown does not help. P at fixed blocks of 5, 21 and 63 days is shown beside it and is not judged.

3.6 Test 5: sub-period stability

The question. Did it work in every stretch, or did one period make all the profit?

Gapw=Sharpestrategy, w−Sharpebenchmark, w

Method. Split the run into 4 equal windows that do not overlap, and take the arithmetic Sharpe gap to the benchmark in each, with Rf at 5%. Windows under 60 days are dropped. If the card says the rules fit parameters to data, the first 5 years are skipped and the test is a walk-forward. Pass: green when at least 50% of windows have a gap above 0 and no gap is below -1.0; amber while the worst gap is at least -1.5; otherwise red. If it fails: the edge depends on when you measured it.

Watch out: it is judged against the benchmark, so a weak market does not fail it. If the rules fit no parameters, these are sub-periods, not out-of-sample tests.

3.7 Test 6: factor regression

The question. Once you remove what known factors explain, is any return left? If not, you are paying for research to get exposure you can buy off the shelf.

r−c=α+∑kβk(fk−c)+εt=αSEHAC(α)lags=⌈4(n100)2/9⌉

Method. Regress daily strategy returns on 7 factor index returns, all above the card's cash rate: NIFTY 500, NIFTY MIDCAP 150, NIFTY SMALLCAP 250, NIFTY500 MOMENTUM 50, NIFTY500 VALUE 50, NIFTY500 QUALITY 50, NIFTY500 LOW VOLATILITY 50. α is the unexplained return and βk the loading on factor k. The t-stat is α divided by its uncertainty. HAC (Newey and West, 1987) is a safer standard error, since daily returns depend on each other and volatility clusters. The lag formula sets how many days of dependence it allows. Pass: green when α > 0 and t ≥ 2.0; amber from t ≥ 1.0; otherwise red. The mark is one-sided: a negative alpha cannot be green. If it fails: no reliable return is left after known factors.

Watch out: a factor left out of the regression can make alpha look larger, and the factor indices are backfilled and price-only. The test subtracts the card's cash rate, not the risk-free rate.

3.8 Test 7: performance after publication

The question. Did the edge survive once the idea was public?

Edgeafter=CAGRstrategy−CAGRbenchmark , from the publication date

Method. The same edge as test 3, from the paper's publication date onward. A date given only as a year is read as 31 December of that year. It needs at least 252 trading days after that date; with fewer the row is not run. Pass: green when the edge is above 0%; amber above -2%; otherwise red. If it fails: the result leaned on the years before anyone could have read the paper.

Watch out: a short stretch after publication is weak evidence either way.

3.9 Outside the gate: deflated Sharpe

The question. Try enough versions of a strategy and one will look good by luck. Is this Sharpe higher than the best you would expect from that many versions with no skill, given how noisy and fat-tailed the returns are? (Bailey and López de Prado, 2014.) It is shown with each run and does not affect the status.

Step 1. How high is the luck bar?

SR0=V×[(1−γ)Φ−1(1−1N)+γΦ−1(1−1Ne)]

The luck bar SR0 rises with N (shown with the default V = 1)

Step 2. How likely is it that the true Sharpe clears that bar?

P(skill)=Φ((SR−SR0)n−11−S·SR+K−14·SR2)
InputMeaning
NStrategy versions tried: the versions the paper reports, every distinct version run before, earlier studies on the trial ledger, plus this run's sensitivities. This is a count of versions, not of tests. A re-run that changes no trade is not a new version.
VVariance of the versions' yearly Sharpes. The bar scales with √V, so the result is very sensitive to it. Two answers are shown: V = 1, the default, which sets a high bar, and V measured on this run's variants, which sets a very low one.
SR, SR0Observed Sharpe (arithmetic, over the risk-free rate of 5%) and the luck bar, both per day (÷ √252).
nNumber of daily returns. More history means more certainty.
S, KSkew and kurtosis, where a bell curve has K = 3. Negative skew and fat tails make a given Sharpe less certain.
Φ, Φ−1; γ, eThe bell-curve probability function and its inverse; the constants 0.5772 and 2.718.

Why it is outside the gate. With V = 1 it fails almost everything; with V measured on near-identical variants it passes almost everything. Until V is settled it is reported for the reader and does not decide the status. Watch out: versions are rarely independent, which overstates the penalty.

Not part of Gate B. The monthly block in Part 2, and the capacity figure in 1.4, are information only. run_pipeline.py also has a promotion ladder that reuses some of these statistics at different bars. Lightyear does not use the ladder.

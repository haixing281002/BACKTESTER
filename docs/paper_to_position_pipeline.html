Paper to Position

Where an LLM belongs in a quant research pipeline, where it must not go, and what can go wrong at each of the eleven checkpoints between reading a paper and allocating capital. Built and running — every stage below exists in code; the risks are the ones the build actually surfaced.

LLM owns the step LLM advises, cannot decide Deterministic code Human decision

Read down a column to see who owns that stage. The load-bearing property: no column has an LLM in the deciding row. Models read, draft and critique; code computes and binds; humans allocate.

The pipeline

Eleven checkpoints, and what breaks at each

00

Triage LLM owns

Screen a day's stack of papers from title and abstract alone. Is the mechanism even capable of surviving a long-only, no-shorting, no-derivatives, daily-data-only mandate?

Agent
TriageAgent · claude-haiku-4-5

Cheap model deliberately. A wrong answer costs one unnecessary full read, and the next stage catches it. This is what makes twenty papers a day affordable — most never reach the expensive model.

  • BlindFalse negatives are invisible. A paper wrongly rejected is never audited by anything. We have no feedback loop that would tell us the screen is too tight.
  • JudgementThe real question — "does this mechanism transfer to our constraints?" — is subtle, and we are asking the cheapest model to answer it.
  • InputAbstracts systematically oversell. The screen reads marketing copy, not results.
01

Ingest LLM owns

Read the rendered PDF — layout, tables, equations, figures — and emit a structured, page-anchored analysis of what the paper actually claims.

Agent · biggest single upgrade over string matching
PaperAnalystAgent · claude-opus-5 · native PDF input

The string-matching version found zero results tables in a paper full of them, because LaTeX draws no ruling lines. It read equations as wspy +wagg +wgld with every subscript destroyed, and rotated figure labels backwards as nruter evitalumuC. It could not tell that the same Sharpe ratio appeared on seven different accounting bases, nor catch the sentence admitting a parameter was chosen "after a modest search over various values" — the single most important fact about the paper's headline number.

  • InjectionA research PDF is arbitrary untrusted input. Anyone can put text in a paper aimed at the model reading it. Fencing helps; it is not a boundary.
  • FabricationA hallucinated page citation is worse than no citation — it looks verified. We have no automated way to confirm page 7 says what the model claims it says.
  • CoverageScanned papers, figure-only results, and supplementary appendices hosted elsewhere are all silent gaps.
  • DriftSame paper, same prompt, different run — the extraction can differ. The engine downstream is bit-deterministic; this stage is not.
02

Strategy Card LLM owns Code validates

Draft the card — the only interface between interpretation and the engine — then attack it with a second agent whose sole job is finding what the drafter waved through.

Agents · two, adversarially paired
CardDrafterAgent → AmbiguityCriticAgent · claude-opus-5

The drafter is invested in its own card being coherent, so a separate critic with a separate instruction finds things it rationalised. In our test case the critic caught two real omissions: that the draft ignored the paper's own 19-way parameter sweep when counting trials, and that it silently implemented the paper's weaker forecast while presenting it as the headline mechanism.

  • CorrelatedDrafter and critic share a model. Shared blind spots survive both passes, and we would never see it.
  • Plausible-wrongA card that is coherent and wrong is the worst output this system can produce, because everything downstream runs perfectly on it and the result looks clean.
  • False rigourThe schema constrains shape, not truth. A validated card is not a correct card.
  • IncentiveA critic rewarded for finding things will find things. We have no measure separating real findings from manufactured ones.
A

Gate A — interpretation Human decides

A researcher confirms the economics before a line of strategy code runs. Everything up to here is cheap; everything after is not.

No model involved, by design. The model's job was to build the queue: unresolved ambiguities, low-confidence equations, proxy approvals, conflicting accounting bases. On our test paper it produced 14 items for a human.
  • Rubber stamp14 items × 20 papers a day is not reviewable. The gate degrades into approval-by-default exactly when throughput succeeds — and nothing in the system detects that it has.
  • Automation biasA confident, well-written, page-cited analysis is harder to disagree with than a rough human note, whether or not it is right.
  • FramingThe model wrote the queue. It cannot queue a concern it did not have.
03

Data feasibility Code binds LLM advises

Resolve every series the paper needs against what the fund actually holds. Fail fast — most papers die here, and should.

Agent · advisory only
DataMapperAgent · claude-opus-5

String equality says a series is unavailable. The useful answers are whether anything we hold stands in, what the substitution costs economically, and what to buy — all judgement calls. The model proposed four ranked procurement items and correctly refused a tempting proxy, noting that long-only sleeve returns are dominated by market beta while academic factors are market-neutral by construction.

  • Plausible proxyThe failure mode is a substitution that reads well and is economically wrong. Deterministic code cannot catch it; only a human who knows the data can.
  • ContainedThe gate is binding and the registry is not writable by the agent, so a model cannot conjure data into existence. Disagreements are surfaced, never resolved in the model's favour.
04

Point-in-time data Code only

Freeze a hashed snapshot with full lineage: source bytes, materialised frame, engine code, git commit.

Deliberately no model here. This stage exists to make results reproducible, and inserting a non-deterministic component into the reproducibility mechanism would defeat it.
  • Provenance gapLLM outputs are not reproducible. We preserve the property by freezing the model's card and hashing that — the card is re-derivable even though the model is not. But the critique, the queue and the reasoning that shaped it are not covered by any hash.
  • Version driftA card drafted by one model version and re-drafted by the next are different artefacts. We have no policy for what happens to a two-year-old card when the model that wrote it is retired.
05

Build & execute Code owns LLM picks a template

Run the backtest: daily accounting, costs at the half-spread, look-ahead tripwires, fair alignment of every strategy and benchmark to a common start.

Agent · selection, explicitly not code generation
TemplateMatcherAgent · claude-opus-5

Chooses from eight audited allocator templates. When none fits it returns null and writes a ~30-line specification for a human engineer. It never writes engine code. A model that generates allocators produces the one artefact nobody can review at twenty papers a day.

  • The temptationThis is where everyone wants to let the model write code, and where we refuse. Whether that is correct or merely conservative is the single biggest open architecture question here.
  • ExpressivenessTemplate-constrained means papers needing a genuinely new mechanism queue behind an engineer. That caps throughput in a way we have not measured.
  • ContainedBacktest arithmetic never touches a model. Two planted look-ahead leaks are asserted caught on every run.
06

Research validation Code computes LLM critiques

Walk-forward, sub-periods, stationary block bootstrap, deflated Sharpe, and sensitivity sweeps over cost, lag, target volatility and the cash-rate proxy.

Agent · interprets numbers it did not compute
ResultsCriticAgent · claude-opus-5

Given the full diagnostic table and no stake in the outcome, this is where a model is genuinely strong. It read a lag-sensitivity curve that rises — Sharpe 0.43 at lag zero, 0.47 at lag ten — and drew the right conclusion: a real timing signal decays, so one that improves when traded ten days late carries no timing information at all. That is pattern recognition over numbers, not arithmetic.

  • Ownership biasFramed as reviewing our result, a model may soften. We mitigate by giving it no stake — but we have not measured whether that works.
  • Judge reliabilityWe are using an LLM as a judge on exactly the cases where being wrong is expensive, with no calibration data.
07

Portfolio validation Code computes LLM writes the memo

The step that actually decides: factor fingerprint, orthogonality to the existing book, incremental information ratio, mandate compliance, capacity.

Where the test case died. Alpha of +4.9% against NIFTY 500 became +0.17% with a t-statistic of 0.15 once controlled for the factor sleeves the fund already owns — and incremental IR was negative at every sleeve size. The model's job here is to write that up, not to discover it.
  • NarrativeA fluent memo makes a marginal result read as a considered one. Prose quality and result quality are uncorrelated.
  • ContainedEvery number in the memo comes from deterministic code and is independently checkable.
B

Gate B — investment decision PM / IC decides

Allocate, observe, fix or reject. Eight criteria, six of which were failing on the test case.

No model votes. Gate B is a deterministic function over evidence, with a human owner.
  • FramingThe model assembled the briefing pack. What it chose to foreground shapes the decision even though it casts no vote.
  • Threshold driftGate thresholds are hand-set constants. Nothing stops them being loosened after a few rejections.
08

Strategy library Code stores LLM recalls

Append-only research graph. Negative results are the asset: they stop the firm paying twice for the same disappointment.

Agent · semantic recall over past failures
LibrarianAgent · claude-opus-5

Cosine similarity over factor loadings catches the same bet under a new name. It does not catch "we tested this mechanism two years ago on different sleeves and it failed for a reason that still applies." That needs reading. On the test case the librarian recommended narrowing rather than repeating: the return question is answered twice over, but the drawdown question is not.

  • ScaleAt a thousand entries the library no longer fits in a prompt. Retrieval becomes its own ranking problem with its own failure modes.
  • Silent suppressionA librarian that wrongly says "already answered" kills a good idea invisibly. Same shape as triage false negatives, and equally unmeasured.

Cross-cutting

Risks that belong to no single stage

Reproducibility

A deterministic engine fed by a non-deterministic front end

Solved for the card by freezing and hashing it. Unsolved for everything else the model produced — the critique, the review queue, the reasoning that shaped the card.

Correlated failure

Seven agents, one model

Every agent is the same model with a different instruction. A systematic weakness appears at every stage simultaneously and looks like consensus.

Evaluation

No ground truth anywhere

We cannot currently say whether the extraction is 95% accurate or 70%. Building the answer key means a human doing by hand exactly what we built this to avoid.

Security

Untrusted documents by design

The system's purpose is ingesting PDFs from anywhere. The structural defence — schemas, no execution, no data-access widening, human gates — bounds the damage rather than preventing the attempt.

Human factors

The gate erodes as throughput succeeds

The better the pipeline gets, the more items reach each gate, and the less real scrutiny each receives. Nothing currently measures this.

Selection bias

Trial counting across agents

The deflated Sharpe penalises configurations tried. If an agent silently retries a drafting step with different framing, is that a new trial? We do not count it.

For the meeting

Questions worth an expert's time

Ordered by how much a good answer changes what we build. The six marked ask first are the ones where we are genuinely stuck rather than merely curious.

Evaluation & trust

01 — 05

ask firstHow do I build an evaluation set for paper extraction without hand-labelling hundreds of papers?

Why: I cannot currently state an accuracy number for Step 01, so every downstream claim rests on an unmeasured foundation. Hand-labelling is precisely the work the pipeline exists to eliminate. Is there a bootstrapping approach — papers with published replication code as ground truth, or inter-model agreement as a proxy?

ask firstHow do I detect a citation that is confidently wrong — where the model cites page 7 and page 7 does not say that?

Why: A fabricated page reference is worse than none, because it looks verified and a human skips it. Is there a cheap verification pass — a second model checking the quote against the page, or the citations feature — that catches this at volume?

Is an LLM a reliable judge of its own pipeline's statistical output, and how would I calibrate it?

Why: The results critic correctly identified that a Sharpe rising with implementation lag means no timing information. That impressed me — which is exactly when I should be suspicious. I have one anecdote, not a calibration curve.

How do I measure the failure I structurally cannot see — the good paper my triage agent rejected, or the good idea my librarian said was already answered?

Why: Both are silent. Nothing downstream ever audits a rejection. Is periodic sampling of rejects the standard answer, or is there something better?

Does confidence self-reporting actually carry information, or am I routing human attention on noise?

Why: My whole human-review queue is built on the model's own confidence ratings. If those are uncorrelated with correctness, the queue is arbitrary and I would rather know.

Architecture

06 — 10

ask firstI refuse to let the model write engine code, only select from audited templates. Is that the right line, or am I giving up most of the value?

Why: It is the largest deliberate constraint in the design. Papers needing a genuinely new mechanism queue behind a human engineer, which caps throughput. If generated code is acceptable, what does the review and sandbox setup have to look like for a strategy that will eventually touch real money?

ask firstMy drafter and my critic are the same model with different prompts. Is that adversarial pairing worth anything, or does it just launder correlated errors into apparent consensus?

Why: The critic did catch two real omissions. But a shared blind spot survives both passes and I would never see it. Would a different model as critic be materially better, or is prompt diversity enough?

Where is the right boundary between structured outputs, tool use, and an agentic loop for this kind of extraction work?

Why: Everything is currently one structured call per agent, no loops. It works and it is easy to audit. Am I leaving accuracy on the table by not letting an agent iterate — re-reading sections, checking its own claims against the document?

Should the librarian use retrieval or long context as the research graph grows past a thousand entries?

Why: Semantic recall over past failures is the compounding asset of the whole system. It currently fits in a prompt. It will not. Retrieval introduces its own ranking failures precisely where a miss is silent.

Is my triage model too cheap for the judgement I am asking of it?

Why: "Does this mechanism transfer to a long-only mandate?" is subtle, and I am asking the smallest model. Is there a principled way to pick the tier, or is it purely empirical?

Safety & failure modes

11 — 14

ask firstMy system ingests arbitrary PDFs by design. How seriously should I take prompt injection, and what does a real defence look like beyond fencing and hoping?

Why: My structural argument is that the blast radius is bounded — schema-constrained outputs, nothing executed, no data-access widening, human gates. Is that argument actually sound, or am I missing a path from a poisoned paper to a bad allocation?

ask firstHow do I stop my human gates degrading into rubber stamps as throughput rises?

Why: One paper produced 14 review items. Twenty papers a day is 280. The gate fails exactly when the pipeline succeeds, and automation bias means a confident page-cited analysis is harder to push back on than a rough human note. This worries me more than any technical risk on the list.

What does a plausible-but-wrong Strategy Card look like in practice, and can anything but a human catch it?

Why: It is the worst output the system can produce: everything downstream runs perfectly, the report looks clean, and the conclusion is wrong. Schema validation constrains shape, not truth.

Is a critic agent rewarded for finding problems reliably distinguishable from one manufacturing them?

Why: A critic that always finds something is as useless as one that never does, and I have no measure that separates the two.

Reproducibility & governance

15 — 18

Is freezing and hashing the model's output enough to call a research result reproducible, when the process that produced it is not?

Why: My claim is that the card is re-derivable even though the model is not, so the engine keeps its determinism. I want that argument stress-tested by someone who will be harder on it than I am.

What happens to a two-year-old Strategy Card when the model that drafted it no longer exists?

Why: Compliance will eventually ask how a live strategy was originally derived. I have no versioning or re-validation policy, and model IDs are pinned in code with nothing enforcing it.

How should agent-driven work be counted in a selection-bias correction?

Why: My deflated Sharpe penalises the number of configurations tried. If an agent quietly re-drafts with different framing, is that a new trial? Agents make trials cheap, which makes the correction matter more and the count harder.

Which decisions should a regulated fund never delegate to a model, independent of how good the model gets?

Why: I drew my line at "models interpret, code computes, humans allocate". I would like to know whether that is where people who have deployed this in regulated settings actually draw it.

Operations

19 — 20

At twenty papers a day, what breaks first — and is it anything I have listed?

Why: My own profiling says compute is not the constraint: most papers die at the data gate in seconds. I believe the real bottleneck is card authoring and human review. I want that challenged by someone who has run this at volume.

What does the monitoring look like — how would I know the pipeline's quality had degraded before a bad strategy reached the IC?

Why: I have per-call provenance and token accounting, but no quality signal at all. A silent degradation would show up as a slightly worse hit rate months later, which is far too late.
